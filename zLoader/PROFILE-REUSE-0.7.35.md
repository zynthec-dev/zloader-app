# Compatible profile reuse — 0.7.35

Paid-team refresh/update/signing now checks existing authorization before issuing or regenerating a provisioning profile. Candidates are the installed zLoader host/extension profile, IPA-embedded/explicit/local profiles, then portal profiles downloaded by their IDs. A compatible profile is returned unchanged, regardless of whether it was originally created by zLoader or Xcode. Duplicate names do not select a profile or force creation.

Reuse requires the exact resolved bundle ID and developer team, a valid expiration, the active signing certificate, every requested entitlement/App Group and every selected registered device. Checks are independent for the host and each extension. When exporting/signing for all registered iPhone/iPad devices, a single-device profile is not reused unless it covers that complete device set.

Only if no candidate fits may an owned incompatible profile be regenerated by ID, or a new uniquely named profile be issued. Download failures are not interpreted as absence or authorization. No portal profiles are deleted. An unchanged reused profile retains its original expiration; reuse does not claim to extend its validity.

Validation: existing profile authorization tests and all-device/case-insensitive device-set regression cases; transport, App Group and context tests; Release build and bootstrap IPA audit. Real Apple acceptance and physical refresh/update remain device acceptance checks. Free-team automatic provisioning retains its existing Apple-managed path.
