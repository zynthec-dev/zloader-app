# Signing and Developer Portal UI — 0.7.39

- Sign App exposes the same Info.plist, App ID, entitlement, icon, extension and profile editors used by installation. Edit App prepares a temporary copy before signing; pressing Sign also applies selected options when there is no prepared copy. Editing has no provisioning creation step. Cancelling an editor prevents signing. Changing the selected IPA/identity or importing more profiles discards the prepared copy.
- Apple Account signing continues through the managed host/extension profile pipeline. Imported identities use their own team and private key without requiring an Apple login, and every retained extension is checked against its assigned profile. Wildcards resolve to the actual bundle ID; they do not grant additional capabilities. Sign-only never attaches an InstalledApp record or embeds a signing private key in the exported IPA.
- Signed IPA library rows read the app name, bundle ID and icon from the IPA and show a small Signed badge. Details in the context menu reads signing type, team, profile expiry, authorized devices/certificates and signed entitlements separately for the host and each extension. This inventory does not certify another device's installation.
- Signing Identities starts with the active certificate, with certificate import/create controls and links to local certificates, keys and signing requests. Account certificate downloads remain separate from local/imported identities.
- Apple Developer Portal is under the account in Settings, disabled for unpaid accounts. Its certificate inventory provides detail/revocation and confirmed local deletion of a cached copy, not certificate creation/import/download. Apple's remote certificate removal is revocation; a local Delete never claims to remove the portal entry.
- Local certificates: trailing swipe Delete/Revoke, confirmation required. Account certificate inventory in identity management: trailing Revoke, leading Share/Download. Download imports the public certificate; Apple does not supply private keys. Existing local key matching is preserved.
- App IDs/groups: trailing Delete with confirmation, leading Info/Edit/Create Profile. App ID profile creation preselects that exact App ID. An App Group has no provisioning profile of its own; group profile creation opens App ID selection. Info is separate from editing. App ID names are sent in the portal mutation and verified by readback.
- Connection Settings contains only connection method and tunnel interface/peer/reachability. External-app setup controls, shortcuts, provisioning controls and address text fields have been removed from this screen.
- The embedded provider's iOS VPN name is zLoader Local Tunnel, including existing configurations, and user-facing internal-tunnel translations use this name. Pairing File Configuration / Pairing File Konfiguration, Connection Settings / Verbindungseinstellung, Certificates / Zertifikate and Provisioning Profiles / Provisioning Profile are localized in the catalog and Settings storyboard resources.

- Refresh progress uses an opaque, adaptive foreground fill against a native neutral track instead of blending into a tinted Liquid Glass pill. The overall navigation progress bar has a visible six-point height and a contrasting track. Idle buttons keep their existing appearance.

## Verification

Run transport, App Group and context regression scripts, portal serializer tests (including rename with no capability change), managed signing and embedded profile reuse tests, Release build and bootstrap IPA integrity test. No live portal mutations/deletions/revocations are performed during verification. Physical-device editing, swipe presentation, signing, tunnel activation and JIT background execution need device acceptance; a build does not prove those flows work on hardware.
