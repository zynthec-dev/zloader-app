# Self-update handoff — 0.7.42

After upload and signing, self-installation acquires a ready device transport lease, then uses the existing host Home-screen suspension helper immediately before the installation call. The lease and UIKit background task remain active until the install call finishes or fails. No fixed delay, early keepalive stop, process exit or fabricated success is used. Self-update detection compares the actual target bundle ID with the running host, rather than depending on an optional Source database record. Ordinary app installs remain in the foreground. Both IPA and app-directory installation paths use the same ordering.

The helper uses the existing UIApplication suspension selector; this is not a public iOS application termination/relaunch API. Installation can terminate the old process when iOS replaces it. Staged expected version/build reconciliation remains the completion check on next launch. A build cannot establish actual installation: physical self-update, background tunnel continuity and iOS lifecycle must be tested on an iPhone. An already installed older version runs its old updater; installing this release externally once may be necessary before its revised handoff can be tested.

Refresh/install buttons use a circular accent-color progress indicator, a contrasting native track and a subdued percentage label below. While refreshing all apps the section action also shows circular progress; the old navigation bar progress is hidden. New installation previews appear above the installed section before database commit, with native cards, app name/source icon where available and reduced opacity. Existing installed apps being updated also use reduced opacity. These are temporary UI previews, not persisted fabricated InstalledApp records; completion/cancellation removes the previews.
